## post
你的 coding agent，正在给你攒一份明文密钥档案。

Claude Code、Codex、Cursor、Gemini CLI、Cline，几乎都会把完整会话落到本地磁盘：Claude Code 在 ~/.claude/projects/ 下按项目存 JSONL，Codex 在 ~/.codex/sessions/，其余几家也大多是 home 目录下的 JSON 或 SQLite。

存下来的是全量记录，不只是聊天：
· Agent 为了「理解项目」cat 过的 .env、config、kubeconfig，原文都在
· 你为了「先测一下」粘进对话的 API key，原样存着
· 工具调用的输出，比如 env、printenv、curl 带的 Authorization 头
· 报错堆栈里顺手带出来的连接串和 token

这些文件不加密、不脱敏，通常一放就是几周甚至更久。它们还会跟着你的 dotfiles 同步、Time Machine 备份、iCloud/网盘一起走，也会被你机器上任何一个恶意 npm 包、任何一个能读 home 目录的进程扫到。

所以问题已经不只是「模型会不会乱来」。就算模型完全对齐，一次 rm 都没执行过，你的密钥照样在磁盘上躺着，而且比 .env 本身更难管：.env 至少在 .gitignore 里，会话文件你可能都不知道它在哪。

我的做法：
1. 先找到它。去看一眼自己机器上这几个目录有多大，里面 grep 一下 sk-、AKIA、ghp_。
2. 缩短保留期。Claude Code 有 cleanupPeriodDays，别用默认值，按需调短。
3. 不让 Agent 读 .env。用 deny 规则或 ignore 文件把密钥文件挡在上下文之外，让它读 .env.example。
4. 不在对话里粘真 key。需要测就用短期 token、受限 scope，测完立刻轮换。
5. 把会话目录排除出备份和同步。
6. 一旦发现泄露，按已泄露处理：轮换，不要只删文件。

谈 Agent 提效的时候，顺便算一下它在你磁盘上留下了什么。

判断：本地会话就是一份明文密钥档案。安全讨论如果跳过会话文件和密钥生命周期，只谈模型对齐，就是在空谈。

## card
### 封面大标题
你的 Agent 会话，就是明文密钥库

### 一句判断
Agent 读过的每个 .env、你粘过的每个 key，都已经写进本地会话文件

### 四类风险条
1. 读过的文件 | .env、config、kubeconfig 被 Agent 读取后原文入档
2. 粘贴的密钥 | 「先测一下」贴进对话的 key 原样落盘
3. 工具输出 | env、printenv、curl 请求头里的凭证随日志保存
4. 外溢路径 | 备份、网盘同步、恶意依赖都能扫到 home 目录

### 防护清单（主模块，4–6 条短句）
- 找到会话目录，grep 一遍 sk- / AKIA / ghp_
- 调短保留期，别用默认值
- 用 deny 规则挡住 .env，只给 .env.example
- 对话里只用短期、限权 token
- 会话目录排除出备份与同步
- 发现泄露就轮换，删文件不够

### 通栏结论
跳过会话文件和密钥生命周期的 Agent 安全，都是空谈。
