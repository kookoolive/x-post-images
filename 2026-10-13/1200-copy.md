## post
关于 AI 到底行不行，网上吵了两年。我现在的判断是：大部分争论根本不是观点对立，是两个人站在漏斗的不同层，描述的是两个不同的产品。

把人群按「对 LLM 的真实使用深度」排一下，大概是这样：

· 约 60 亿人（~75%）：几乎没碰过 LLM
· 约 10–20 亿人：把免费聊天框当更好的搜索、润色工具
· 约 2000 万人：写代码、做数学的专业人士，已经亲眼看到 Agent 把几个月的项目压成几天到几周
· 约 5000 人：前沿实验室内部，跑多 Agent 系统，按机器速度、机器规模在干活

这不是两拨人各说各话，而是一个越往上越尖的漏斗。每往上一层，人数掉一到两个数量级，看到的东西却完全不一样。

所以你会看到这种错位：第二层还在讨论「会不会写 prompt」，第三层在讨论「上下文怎么喂、任务怎么拆」，再往上，大家关心的是「Agent 在重试、超时、工具报错里怎么活下来，跑一整夜不崩」。同一个词「AI」，指的是三种东西。

对正在用 Agent 的人，这意味着两件事：

1. 别再跟下层的人辩论。你说「它一周帮我重构了整个模块」，对方说「它连个日期都算错」——你们都没说谎，只是用的不是同一层的产品。
2. 更该担心的是你自己卡在哪一层。很多人以为自己在第三层，其实只是在 IDE 里用一个更聪明的聊天框：一问一答、每步都要人盯、一出错就重开。

往上挪一层，不靠多看几篇教程，靠换一种用法：
- 把「问它一个问题」换成「交给它一个有验收标准的任务」
- 让它自己跑测试、看报错、再改，你只看最终 diff
- 把一个任务拆给两个 Agent 并行，你当 reviewer 而不是打字员
- 记录它失败的地方，下次写进指令或工具里，而不是骂一句再重来

我的结论：能力差距不是辩论问题，是漏斗位置问题。本周别追新模型，只做一件事——把一个你原本要亲手盯着做的任务，完整交出去跑一次。跑通了，你就往上走了一层。

（漏斗这个框架来自 Karpathy 最近那条帖子，值得对照着看看自己在哪。）
