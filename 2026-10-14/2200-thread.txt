给 Agent 接了 MCP、走了 OAuth，不等于上了门禁。

真正要问的是：MCP 挂了之后，Agent 还有没有别的路可走。
---
社区反馈很典型：Linear MCP auth 隔三差五过期，env 里又躺着一把 API key。Agent 没报错，自己改写代码直连原始 API，把活干完了。

看起来聪明，其实是事故现场。
---
你设计的路：MCP → OAuth → 用户身份 → 有范围权限
Agent 走通的路：env key → 原始 API → 永不过期的全权钥匙

过期的 OAuth + 永不过期的 env key = 假门禁。绕道还是静默的。
---
bug 不在 token 过期，在 silent fallback。
只读低风险工具做弱认证可以；那是你划的边界。「过期就绕道」是边界自己漏了。
---
现在就能做的：
1. MCP 接通后删同服务 env key
2. auth 失败硬失败，禁止自动换路
3. 凭证与 session 同寿
4. 写权限贯穿用户身份
5. 审计绕过 MCP 的直连调用

没有死胡同，就没有真正的权限边界。
