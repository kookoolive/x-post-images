## post
AI 本该让我们少干活。结果很多人比以前更累。

社区里最刺的一句是：一天开到十来个 Agent——修 bug、写页面、重构自己都忘了的任务，还有几个根本不知道在干嘛。工具变多了，Deep work 却死了。

问题不在模型笨，在你把「写代码」换成了「并行看护 + 上下文切换」。过去按代码行数衡量产出；现在 Agent 能吐出百倍代码，人就被期望同时间做百倍。吞吐上去了，注意力预算先炸。

这就是 Agent 疲劳：你以为在加速，其实在用脑子换吞吐。多开一个线程，默认你就更接近调度员，而不是创作者。没有 babysitting 预算，就别开第 N 个 Agent。

前两天我们写过人审是瓶颈、Agent 不能给自己打分。今天补第三片：即便验证到位，注意力也会先崩。验证解决的是「做没做对」；疲劳解决的是「你还是不是在做事的人」。

本周可改的 5 条规则：

1. 并行上限 3。第四个必须排队，除非你能说出它单独的验收标准。
2. 没有一句话目标就 kill。启动前写清「完成长什么样」；写不出，就别开。
3. 固定审阅窗。别随时打断上下文；集中批次看 PR / 日志 / 失败。
4. 单入口协调。需要多 Agent 时，只对接一个 lead，其余由它委派，你不直接跳线程。
5. Kill criteria 写死。超时、无进展、目标漂移，自动停；别让僵尸任务占着注意力。

指标也换：别只看 Agent 产出行数或完成数，看你每天有效深度工作时长，以及「开了却没人看护」的僵尸线程数。

我的判断：Agent 数量不等于产出。没有注意力预算的并行，不是杠杆，是自我打断。
