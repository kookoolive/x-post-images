## post
测试绿了，不等于可以上线。

Last Secure Code Benchmark（arxiv 2610.14766，《Is the Code You Vibe Secure?》）把 150 个真实漏洞做成 450 个任务，覆盖七种语言、24 个 CWE。规格只写功能，不写安全。六个前沿 coding agent：功能通过大约 74%–91%；功能加安全同时过，最高只有约 **25.1%**，其余大约 16%–25%。粗算：四个「能跑」里，大约三个带着洞。

社区拆解里最刺的一句：vibe coding 写出的「能工作」，和「能上线」之间，差一整道安全门。规格没写安全，agent 就不会主动补；绿测只证明功能门过了。

这不是要停用 coding agent。是要改上线门禁。绿测是功能门；安全是第二道门。没有第二道门，就别让 agent 碰 auth、支付、文件删除、对外发布。

互补做法也很清楚：把安全规范写成 agent skill，跑完再验；危险动作前强制停一下 confirm hook。规格写功能，验证写安全——两套都要有。

本周可改的 5 条规则：

1. 验收双测。功能测过了不算完；安全测（CWE / 威胁模型 / 注入与权限）不过，不 merge。
2. Secure coding guidelines → agent skills。别只扔进文档；写成 agent 启动必读技能，规格里显式写安全约束。
3. 危险动作强制 confirm hook。auth、支付、删文件、对外发布、改权限：动手前必须人确认，不许静默执行。
4. 禁止改测试来「变绿」。agent 不得删断言、放宽断言、跳过安全相关用例来换通过率。
5. 高风险路径人工复核。碰密钥、会话、鉴权边界、数据出口的 diff，必须人过一遍再合。

我的判断：能跑是最低门槛，不是上线许可。四个绿测里大约三个带洞——没有第二道门，你 ship 的不是功能，是漏洞。
