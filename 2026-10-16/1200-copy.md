## post
Agent 会看盘、会下单、会调钱包。问题从来不在它聪不聪明——在谁能动钥匙。

Ledger 昨天甩出 Agent Intent：Agents propose → Humans approve on Ledger signer → chip enforces。钥匙永不进模型。同日 Mercury MCP（支付排队进审批）、Self Agent Vault（占位凭证，真钥用时才换入）——三家同形：Agent 只能提案，人在独立审批面点头，硬件/签名器强制执行。

这才是 Agent 经济真正的瓶颈：信任，不是智商。聊天窗口里点「同意」太便宜了。弹出多了就变成同意疲劳——批着批着全点过，等于没批。高风险动作（转账、密钥、部署、删库）需要和聊天物理/产品隔离的审批面：硬件签名器、独立队列、单笔强制看摘要。

我的判断：把确认写进 prompt，是安慰剂；把确认写进芯片，才是基础设施。

本周可改的 5 条规则：

1. 高风险清单写死。转账 / 密钥 / 生产部署 / 删库，必须走独立审批面，禁止在聊天里一键过。
2. Agent 只能 propose。会话里不持钥、不持支付 token；真凭据只在审批通过后由签名器释放。
3. 审批面与聊天隔离。硬件签名器或独立审批队列；同一窗口里的「确认」一律不算数。
4. 防同意疲劳。批量审批默认拒绝；单笔超时自动否；强制展示金额/目标/影响摘要再点头。
5. 审计可回放。谁批了什么、何时、哪把钥匙——日志可追，出事能复盘。

Agent 时代拼的不是谁先放开权限，是谁把「人在硬件上点头」做成默认路径。
