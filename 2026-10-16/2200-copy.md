## post
「给公司造一个 AI 大脑」这条路，BabyAGI 作者 Yohei Nakajima 自己掉头了。

他在做 FirmOS 时改了方向：组织里的 Agent 协作，未来更像一个「公司操作系统」CompanyOS——人和 Agent 一起用，而不是一个什么都往里装的 Company Brain。这条帖 565 赞、568 收藏。LangChain 的 Harrison Chase 顺手画了路线：coding agents（Claude Code、Codex）→ personal agents → companyOS（???）。

区别在哪：大脑是一堆知识，指望装进去就会懂。OS 存的是规则、流程、该用哪个工具，而且每天被人和 Agent 一起改；真源仍留在 CRM、文档这些原系统里，不再复制一份。

我的判断：company brain 卡住，不是因为检索不够好，是它没回答三件事——谁能看、谁能改、谁对结果负责。OS 这个比喻好就好在天然带着这三样：权限、进程、日志。

评论区最值钱的几条：Agent 替初级分析师干活，不该看到 CFO 的 Agent 看到的东西，权限要跟着它代表的人走；员工离职时，什么留在公司、什么能带走；Agent 写进去的周报，总得有个具名的人来收口。

想在团队里试 CompanyOS，本周可以先做 5 件事：

1. 不搬数据。真源留在 CRM / 文档 / 工单，OS 只存「规则 + 流程 + 工具用法」，链接回去。
2. 权限跟人走。每个 Agent 绑定一个它代表的人，继承那个人的可见范围，不开公司级通行证。
3. 流程可改，改动留痕。人和 Agent 都能改流程，但每次改动有作者、有 diff、能回滚。
4. 每条流程一个具名 owner。Agent 跑、人收口；没有 owner 的流程不上线。
5. 先定离职边界。哪些上下文属于公司、哪些属于个人，现在就写下来，别等人走了再吵。

Coding agent 管代码库，personal agent 管你的一天，下一个要管的是整个组织。拼的不是谁的大脑装得多，是谁的 OS 权限分得清。
