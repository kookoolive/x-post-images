## post
HN 昨天冲上榜首的 Sphinx，干了一件很反潮流的事：你或 Agent 往 main 推代码时，Git 先停住——另一套评审模型只读本次 diff，就「失败时会发生什么」出题；答错先讲解再换场景，答对才放行。急着用？`sphinx yolo`，但跳过会被记下来。

它在治的不是「AI 写得慢」，而是「写得比人看得懂还快」。代码能跑、测试绿、PR 也过了，可你仍然说不清 webhook 重试为什么会漏扣款——这种语义缺口，Agent 最爱留下。

我的判断：验证回路可以交给 Agent；「我懂不懂这次改动」不能。Sphinx 把懂不懂从 code review 态度，变成了 push 门禁。门禁可以绕过，但绕过有日志——比假装自己看过了，诚实得多。

本周 5 件事：
1. 挑一个保护分支（main / release），装一次 pre-push 理解检查，先只拦生产向。
2. 题库优先问失败模式：重试、超时、幂等、权限降级——别只问「这段代码干什么」。
3. 出题模型与写代码的 Agent 分开；答案不要回灌进写码会话。
4. 允许 yolo，但每周看一遍跳过日志：哪类改动最常被跳，那就是团队的盲区。
5. 新人入职第一周：不只派「让 Agent 写」，也派「解释 Agent 刚写的 diff」。

代码越来越像生成物。门禁如果只拦语法和测试，拦不住「没人看懂」的仓库。
