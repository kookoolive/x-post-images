一篇跟了 6774 条已合并 Agent PR 的论文，问了一个很少有人追的问题：合并之后 30 天，还要不要再修？谁来修？

对照同仓库同期 5044 条人类 PR：Agent 合并后拿到「已核实后续修复」的几率，是人类的 1.62 倍（4.5% vs 2.3%）。一半发生在第一周。五家里 Codex 最高 5.5%，Claude Code 最低 3.2%（样本少）。

更有意思的数字：这些修复里，69.6% 来自同一个 Agent；整条修复 PR 全是 Agent 提交的占 76.4%。人只干了约四分之一的收尾。

我的判断：Merge 率量的是「审阅者放行」，30 天修复率量的是「改得对不对」。多数 Agent 看板只盯前者。Agent 会自己回来擦屁股——但前提是配置、上下文、模型还在。模型下线、vendor 换代、原始意图从没写进 PR 时，70% 的维护就断了线。

本周 5 件事：
1. 给自己的 Agent 产出加一条 30 天「合并后修复率」查询（同文件、fix 标签、30 天内）
2. 按 Agent / 仓库 / 任务类型拆开看，别只看全库均值
3. 修 Bug 时把原 PR 正文和 spec 喂回去，别只丢 diff
4. PR 描述强制写意图与约束——那是 Agent 唯一会留下的记忆
5. 审查时间偏短、评论偏少的合并，事后多盯一周：论文里这类更容易再修

绝对差只有大约每百条多两修。值得追踪，不值得恐慌。真正该改的是成功指标：别再把「合并了」当成完工。
