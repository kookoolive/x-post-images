## post
点批准五十次，不等于更安全。

Anthropic 10/22 官宣：下周起，Claude 网页、桌面、手机端的新会话，对 Pro / Max / Team 默认进 auto mode——不再每步弹窗，改由独立分类器放行安全动作、拦住高风险；随时可切回手动。Claude Code 八月起已是默认。

测试数字刺眼：付费测试里塞进危险命令，auto mode 拦下 89%；人点 Approve 只抓到约 14%。Gusto 的反馈更直接：权限疲劳会把工程师推向「干脆绕过检查」。

我的判断：产品默认面从「先问人」翻成「先信护栏」，等于承认橡皮图章式批准已经失效。真正该守的不是「有没有弹窗」，是不可逆、出环境、动钱删库这类动作有没有硬闸。把安全寄托在狂点批准，是在用仪式感冒充审计。

本周 5 件事：
1. 划定仍须手动的面：动钱、删库、发生产、外发消息——写进团队约定，别靠习惯
2. 别把 Approve 点击当审计日志；需要留痕就记「拦了什么 / 放了什么」
3. 自建 Agent 产品：分类器 / 策略层放在 UI 确认之前，别倒过来
4. 用自家危险命令清单压一遍护栏，别只信厂商百分比
5. Enterprise / API / 云端仍是 opt-in，组织默认改之前先定 managed settings

默认一翻，安全叙事就变了：比的是护栏能不能拦，不是人能不能点。
