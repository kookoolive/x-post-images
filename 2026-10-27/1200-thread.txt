测不过的 Agent，只是带 API 的 vibe。

Cursor 刚把 Agent SDK 做成正式产品：Agent 不再是一段藏在对话框里的提示词，而是一个可版本控制的文件夹——instructions.md 当系统提示，tools/ 里每个文件是一个类型化动作，skills/ 按需加载，mcp-connections/ 接外部工具，channels/ 定义它从哪醒来（PR、Slack、webhook、cron）。
---
本地 agent-sdk dev，部署 agent-sdk deploy，托管或自建都行。Bugbot、Security Review、Approval Bot 用的就是同一套 harness。

真正值钱的不是「又能写 Agent 了」。市面上同类 SDK 已经不止一家。
---
真正值钱的是内置 eval：发一条固定消息，断言它调了哪些工具、参数长什么样、回复形状对不对；还能把真实 PR 重放成 webhook fixture，推进 CI。

Agent 终于有了代码早就有的东西——测试和版本控制。
---
以前改提示词靠感觉：觉得「好像更好了」就上线。现在改动可以 hillclimb：一次改一点，用 eval 锁住胜利，回归挂掉就回滚。

不能测的 Agent，本质上还是 vibe coding，只是包装成了产品。
---
做 Agent 产品的人该改口径了：别再问「这个 Agent 聪不聪明」，先问「它有没有 10 条会失败的 golden case」。

没有断言的发布，只是把不确定性推给用户。
---
本周 5 件事：
1. 把最常翻车的 3 个场景写成 eval（工具调用 + 回复形状）
2. 提示词进仓库，跟代码同 PR 审
3. 写操作工具在 eval 会话里禁副作用
4. PR / Slack 触发的 Agent 用真实事件重放，别只测 happy path
5. 模型可换，eval 契约先钉死

没有测试的 Agent，别叫产品，叫演示。
