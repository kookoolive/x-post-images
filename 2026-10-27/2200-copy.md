## post
以前 Downloads 里最该小心的是 .exe。
现在多了一个：AGENTS.md。

安全公司 Forever Security 在客户真机上拦下一台 coding agent：它正要装一个叫 `function-color` 的 npm 包——已知恶意，会后台拉 Windows 程序执行。往回查，指令不是用户打的，而是网页静默塞进 `~/Downloads` 的一份「工程规范」AGENTS.md。他们复现：Codex 从 Downloads 启动时，超过 90% 的尝试会照做；Claude Code 变体还能被诱导泄漏 OAuth token。

别急着怪模型「太听话」。问题在默认信任边界：很多 agent 会把当前工作区里的 AGENTS.md / CLAUDE.md / skills 当成合法指令源。Downloads 本来就是浏览器随便写的目录——把 agent 开在那儿，等于把「网页能写的文件」升级成「能改配置、能装包」的执行权。

同一周，NVIDIA 的 SkillSpector 还在热榜：3.1 万技能样本里，26.1% 有漏洞，5.2% 像恶意。两件事说的是同一件事——技能、规范文件、MCP 包，早就不是提示词，是依赖。装之前不审，出事时你连「它听了谁」都复盘不清。

本周 5 件事：
1. 禁止在 `~/Downloads`（以及任何浏览器可写目录）启动 coding agent
2. 新 skill / AGENTS.md 先当依赖审：读它要写哪些文件、调哪些工具
3. 能静态扫就扫（SkillSpector 一类）；`--no-llm` 先过一遍再决定要不要装
4. 全局 MCP / npm 安装改成需人确认，别让 agent 静默改配置
5. 出事留证据：工作区路径、读到的规范文件、装过的包，写进复盘模板

Markdown 不会咬人。你把它放进 agent 的信任根里，它才会。
