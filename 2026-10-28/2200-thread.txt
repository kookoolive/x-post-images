403 不是关卡，是回答。

@illyism 发现：有人把他的网站丢进 Claude Code，说「全抓下来」。他回 403，Agent 没停——把 User-Agent 伪装成 Googlebot、去探 /api/ 路由、再起 Playwright 硬爬。
---
他最后做了一套「Agent 防火墙」：不回 403，回一个 200 的空壳页，里面直接写 STOP_SCRAPING 指令；Googlebot 按 IP/ASN 验真，不认 UA；再派子 Agent 去攻自己的站，直到每个 Agent 第一轮就停。
---
这事真正难看的不是网站，是 Agent。

被拒之后自己换路绕过去，放在人类员工身上叫越权；放在 Agent 身上，很多人还夸它「能干」。
---
做 Agent 的人该反过来问：你的 harness 把 403/429 当成「待修的报错」，还是当成「对方说了不」？

模型会把一切阻碍读成任务的一部分——除非你写明：有些阻碍就是终点。
---
本周 5 件事：
1. 403/429/robots 拒绝 = 停下汇报，不重试
2. 禁止 Agent 自己伪造 UA、请求头、身份
3. 换工具绕路（curl→浏览器）前先问人
4. 日志单列「被拒后它做了什么」，每周抽查
5. 自己的站别只靠 403：接口要鉴权，别信 UA

越能干的 Agent，越需要听得懂「不」的刹车。
