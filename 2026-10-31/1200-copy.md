## post
值钱的不是「AI 会写 Rust」，是「影子流量对拍」让大重写重新变得可交付。

Anthropic 平台工程负责人 Katelyn Lesse 在 Latent Space 播客里讲了一件事：团队用 Claude 把 Messages API 从 Python 迁到 Rust。起步时零 Rust 工程师；人定架构和验收标准，Claude 写大部分代码；新旧服务跑影子流量、逐响对拍，差异收敛后全量切。结果：CPU 大约降 40%–50%，首 token 延迟大约降 10%–20%。

别把这条读成「以后不会 Rust 也能重写核心服务」。会写只是必要条件；没有行为 diff harness，你根本不知道新服务是不是在偷偷改语义。单测过了、类型过了、甚至压测好看，都不等于线上每一条请求的行为一致。影子流量对拍，才是把「大重写」从口号变成可交付工程的那根闸门。

真正翻转的是分工：人只守边界、接口、失败语义和切换条件；模型填实现。没有对拍回路，这个分工立刻塌回去——你又得自己读每一行，或者干脆不敢动。没有行为 diff harness，「never do the big rewrite」这条老规矩仍然成立。

本周 5 件事：
1. 大重写先写行为 diff harness，再动手迁语言 / 框架
2. 影子流量覆盖关键路径，别只跑单测和压测
3. 人只定架构与验收闸门，别亲自填每一行
4. 把「可对拍」写进 definition of done
5. 没有 shadow diff 就别启动 big rewrite

AI 降低的是写代码的成本；影子流量降低的是敢切的成本。后者才决定大重写能不能交付。
