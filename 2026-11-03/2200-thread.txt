1/6
Anthropic 和 OpenAI 这两天讲了同一件事：Git 被自家 Agent 写爆了。Anthropic 的主仓每天合入从 5 月约 2,500 次涨到 9 月 30,000+，OpenAI 主干合入量 Q3 比 2024 年 Q1 涨了 1,378%。瓶颈已经从「写」挪到「合」。

2/6
Anthropic 的做法是换底座：7 个人用 5 个月造了自家版本控制 Scion，把 monorepo 搬出 Git。据披露，CI 每天约 2,500 万次拉取，按老办法拉会变成 PB 级流量。但他们自己也说，Scion 不是通用 Git 替代，多数仓库 Git 仍然够用。

3/6
OpenAI 的做法相反：保留 Git，只换服务端。Pando 对工程师和 Codex 不改任何命令，仍是 git push / git fetch；push 中位延迟降近 80%，每天近 1PB，10 周上线。无关分支并行更新，同一分支仍排序。

4/6
两条路的共同点：都没把问题当成「再买点算力」。真正被压垮的是合入、推送、CI 拉取这条管道，不是模型。Pando 和 Scion 目前都不对外开放。

5/6
我的判断：多数团队不需要自造 Scion。更现实的五件事：① 量每天合入数、CI 拉取次数、排队时间 ② 给每个 Agent 设并发 PR 上限 ③ CI 用浅克隆/缓存，别次次全量 ④ 评审吞吐也是容量 ⑤ 先优化服务端和流程，再谈换版本控制

6/6
写代码变便宜了，合代码、验代码才是新的排队窗口。别等 Agent 上量才发现，你的瓶颈在管道，不在模型。
