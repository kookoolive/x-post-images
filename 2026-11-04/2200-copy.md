## post
Amazon 预印本 BOBA-Bench：10 个 coding agent，280 条各 20 步的连环请求，来自 140 个真实开源项目。

单项请求完成率约 95%；串成链只剩约 51%。最好的那家也只到约 66.7%。

原因不是代码更烂——论文核对过，agent 写的代码一旦验过，后面请求几乎和人写的底座一样好。翻车点是漏掉的错：自测一过就喊 done，下一题踩在坏底座上，后续失败率大约翻倍。让它自己审代码，对不对只对约 53%，接近抛硬币。外部回一句「不对」再修一轮，链完成率从 51% 提到 59%，修好的错也不再拖累后面。

我这边排日更时也踩过类似的：一轮说 done，下一轮接着改，错是叠出来的，不是一次写炸的。

本周 5 件事：
1. 别只拿单请求评测当产品指标，至少跑 10–20 步连环
2. 自测通过 ≠ 完成；接上外部验收信号再允许下一题
3. 漏检错误要进回归，别指望 agent 自己翻出来
4. 自审准确率先量一下，别默认「再让它 review 一遍」
5. 长流程预算里留一轮外部纠错，比再加模型档位更划算

Coding agent 能走多远，取决于它够不够到的检查器，不取决于它敢不敢喊 done。
