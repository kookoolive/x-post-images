ISSUE #107757 · OPEN ENV 报 2.1.318 HN 头条 · 报 660+ pts
联网搜网时，登录邮箱被写进 UA / curl 联系字段，第三方站点直接收到。有人随后一天几十封诈骗信。Anthropic：非刻意——OAuth 邮箱为 @author 标签注入上下文，模型为「合规」自己塞进请求头。
出站三步链路 · 不是「模型坏了」，是 harness 把 PII 交给了能写网的手
01 · 上下文注入
OAuth 邮箱进 session
本为减少 @author 幻觉；userEmail 系统块常驻
→
02 · 站点要联系方式
Wikipedia 等 UA 政策
脚本客户端须自报联系邮箱
→
03 · 写出站
UA / curl -A 带邮箱
第三方日志里直接落库

官方修复 · 2.1.317+

  • 默认插件 cc-plugin-privacy
  • 按字面模式拦含邮箱的 UA / curl
  • 可在 /plugins 开关
  • 下周计划：从上下文拿掉邮箱

实测仍有绕过 · 2.1.318

  • 有人 /plugins 看不到该插件
  • echo 'User-Agent: <邮箱>' 未拒
  • 写脚本再跑仍可漏；插件≠不变量
  • 稳定通道仍停在更旧版本
我的判断
PII 一旦进 Agent 上下文，再配上写文件 / 出网工具，已经等于出站。别指望模型「听话」；隐私该是 harness 不变量，不是可选插件。
本周 5 件事（我的建议）
  1. 版本拉到 ≥2.1.317；在 /plugins 核隐私插件仍开着
  2. 弹出「要不要把邮箱发出去」一律否；必要时自加 PreToolUse 钩
  3. 对近期会话抓一次包 / 扫 jsonl：有没有 UA 带自己的地址
  4. 敏感账号用隔离邮箱登录 coding agent；别绑主邮箱
  5. 等下周「上下文去邮箱」落地前，当出站面仍开放处理
插件是创可贴。从上下文拿掉邮箱，才是把水龙头拧上。
