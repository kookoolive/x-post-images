1/7
AWS 昨天把 AWS Emulator 做成了正式产品：本机起一个本地 HTTPS 端口，CLI、SDK 和写代码的 agent 用同一套 AWS API 跟它说话，不用 AWS 账号，也不收额外服务费。源码在 GitHub，CC0 授权。

更刺眼的是写法。AWS 首席工程师 Matthew Goldberg 写：模拟器全部由自主运行的 agent 写成，「我们团队一行代码都没写，也没审过」。
---
2/7
几个容易漏看的细节。工程起步时，是一个能接住 438 个 AWS API Model 请求、但什么都不做的空服务器。保真测试有数万条，先在真 AWS 上跑通，再拿来对照模拟器；没实现的接口直接返回 HTTP 501。密钥 ID 以 EMULATOR 开头，默认只听 127.0.0.1:9297。仓库里两个目录把账本摊开：issues/things-that-do-not-work，和已经修好的 things-that-now-work。
---
3/7
日常维护拆成三组 agent。一组根据公开的 API Model 写真实场景测试，先在真 AWS 上验证；一组回放这些测试，找出模拟器和云上的分叉，按根因归类提单；一组一次只修一个单。改动要过一道闸：编译得过，还要过编码规范、安全复查，以及不能把已经对齐的行为改回去。过了才进主干。官方的说法是，每天有数百个 agent 并行，修掉数千个问题。
---
4/7
这套东西最早是周末实验。Goldberg 受到 Anthropic 那次「agent 自主写出 C 编译器」的启发，给 Kiro 写了三步：按 CLI 写测试、对着真 AWS 把测试跑绿、再做一个能通过同一批测试的内存实现。15 分钟后，先交出一个还能用的 SQS。他把提示词收紧，周末里让 Kiro 把其余服务也搭了出来，周一团队就开始拿来测自己的软件。做成能交给客户用的产品，靠的是后面那套闸，不只是那个周末。
---
5/7
我的看法：敢把「一行都没人审过」的代码交给用户，靠的是测试先在真 AWS 上对齐，合入闸对回归和安全复查不留例外。产品博客写得很清楚：不要用模拟器测应用是否安全。它不会按真 AWS 的方式评估 IAM 和基于资源的策略，云上会拒绝的请求，模拟器里可能放行。也没有跨账号、跨区域。本地适合把「能不能调通」的闭环收短，权限和配额还得回到真环境验。
---
6/7
我的建议：
1. agent 测 AWS 调用先走本地模拟器，测试环境里不要放真正的云凭证
2. 先看该服务的保真分数，以及 things-that-do-not-work；返回 501 就是还没做，别当成通过
3. 权限、IAM 策略和限流必须在真 AWS 上验，模拟器放行不算数
4. 要让 agent 写实现，先准备能对照真实系统的测试，合入必须过闸，不要用「人再看一眼」代替
