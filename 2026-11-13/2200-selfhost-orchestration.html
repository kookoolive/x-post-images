模型请求还是要出门

模型搬进机房→编排、凭据、会话留下
Anthropic 把 self-hosted Claude Managed Agents 开了私有测试。开发接口跟托管版同一套，申请走 Anthropic 客户团队，个人订阅申请不了。
INSIDE · 留在你这边
编排和记录不出门
  • harness（编排层）和沙箱
  • 凭据，可放进你的密钥管理
  • 会话历史，存在你的 PostgreSQL
  • 每步工具调用经 OpenTelemetry 导出
OUTSIDE · 还是要出门
模型本身在网络外
  • 出口可选 Anthropic、Bedrock、Google Agent Platform、Foundry，或自建网关
  • 提示词出去，补全回来
  • 有零数据保留协议的，按 Messages API 同一口径算
YOU RUN 01
Managed Agents 服务器
控制面，跑 agent 循环，对外提供同一套 API
YOU RUN 02
PostgreSQL
存 agent、会话和完整会话历史
YOU RUN 03
Sandbox workers
在沙箱容器里执行 shell 和文件工具
127.0.0.1:8400 开发栈明文 HTTP 生产用两套 Helm 不迁移托管数据 无 webhook 无定时部署
OFFICIAL SCOPE · 官方范围
沙箱外的代理把密钥贴上去，官方写明范围是 MCP 和「支持的 API 调用」。agent 还会碰到的其他服务，上线前得自己核一遍。
TAKE · 判断
这是把编排收回来，不是把模型搬进机房。会话记录和凭据落在你的边界里，这层值得自己跑；出口和允许名单没写严，照样会漏。
我的建议
  1. 先分清要托管的是编排还是模型，别把「自托管」理解成模型不出门
  2. 上线前核对接入口径，以及密钥代理覆盖不到的调用
  3. 给每个环境写死允许访问的主机，修构建就只放开 git 和包仓库
  4. 没有 webhook，就自己准备调度和一直轮询的 worker；会话记录接到现有监控里
会话记录可以留下，模型请求还是要出门
