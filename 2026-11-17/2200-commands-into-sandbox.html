CLAUDE CODE · 边界
只有 Bash 会进去
原生 Read / Edit 仍在本机。挂载规则管的是命令能碰的目录，挡不住它直接改你 Mac 上的文件。
网络默认关
  • 要上网加 --proxy，按主机和 HTTP 方法放行
  • 不走代理、试图直连的请求，照样拦
凭证替换
  • 沙箱里只放占位符，真密钥留在本机代理
  • 被放行的主机若在响应里回显，仍可能漏；方法和路径要收窄
实验原型，未审计到可托付敏感工作 可写挂载里的文件，照样能毁掉 客机是 Linux，macOS 的 node_modules / .venv 可能要重装
我的看法最有用的不是又多一层隔离，而是把「模型自己判断能不能继续」和「命令物理上出不去」分开。换更小、可本地跑的模型时，文里把这件事写在前面。
我的建议
1先核这个 agent 有哪些工具会进沙箱。Claude Code 别当成文件操作也被罩住
2默认定网关，按主机和方法开白名单；密钥走凭证替换
3可写挂载只挂当前项目，能只读就只读，目录进 git
4敏感仓库先别用，文里写明还没审计到那一步
