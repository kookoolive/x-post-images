1/9
Simon Willison 和 Prime Radiant 发了一套叫 external sandboxes 的原型。名字要先拆开：external 说的是沙箱在 agent 外面，不是在电脑外面。Agent 还在你的 Mac 上跑，它发出的命令，才进隔离的 Linux。
---
2/9
他们试过两种做法。一种是把 agent 也关进沙箱，比如 Fly 的 Sprites。另一种是 agent 留在外面，只把命令送进去。他们选了第二种，理由写得很直：避免 agent 改到自己和自己的环境，边界也更好审。
---
3/9
三套实现走同一套协议，可以并排开。
v86：Node 在 WebAssembly 里跑 Alpine，端口 8686，要 22.19 及以上。
Apple Containers：Python 封装，8687，需 Apple silicon 和官方 CLI。
Quicksand + QEMU：Python，8688，镜像以 wheel 带上，不用另装。
---
4/9
接入深度不一样。
Pi 1.5 起：bash、read、write、edit、grep、find、ls 都进沙箱；加 --no-builtin-tools，扩展失败也不退回本机。
Codex：进程和文件操作，含原生 apply_patch，走 exec-server。自动测试过 0.164.0，协议仍标实验。启动要用 --sandbox danger-full-access，别再叠一层自带沙箱。
---
5/9
Claude Code 不一样。只有 Bash 会经 CLAUDE_CODE_SHELL_PREFIX 进沙箱。原生 Read 和 Edit 仍在本机跑。挂载规则限制的是 Bash 能碰的目录，挡不住它直接读写你 Mac 上的文件。临时目录 .external-sandbox-claude-tmp 还得放在可写挂载里，因为它拿来记账。
---
6/9
默认没有外网。要上网，加 --proxy，按主机和 HTTP 方法做白名单。直连、不走代理环境变量的请求，照样会被拦。
还有凭证替换：沙箱里只放占位符，真密钥留在本机代理上，请求出门时再换上。被放行的主机若在响应里回显密钥，仍可能漏，只对信任的服务开，路径要收窄。
---
7/9
文里还写了两条使用边界。可写挂载里的东西，agent 照样能毁掉，所以目录要进版本管理，能只读就只读。沙箱跑的是 Linux，项目里给 macOS 编的 node_modules、.venv，可能要在沙箱里重装。
这三套都还是实验原型，没有审计到能托付敏感工作的程度。
---
8/9
我的看法：这套东西最有用的，不是又多了一个隔离层，而是把「模型自己判断能不能继续」和「命令物理上出不去」分开了。Claude Code 的 auto 模式、Codex 的 auto-review，靠的还是模型判断。换更便宜、更小、可本地跑的模型时，文里把这件事写在前面：这些模型更容易出错，也更容易被注入。
---
9/9
我的建议：
1. 先核哪些工具会进沙箱。Claude Code 只用它跑 Bash，别当成文件操作也被罩住
2. 默认定网关，密钥走凭证替换，别写进沙箱环境
3. 可写挂载只挂当前项目，能只读就只读，目录进 git
4. 敏感仓库先别用，文里写明还没审计到那一步
